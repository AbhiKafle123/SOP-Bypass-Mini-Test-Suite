Live probes — running in your browser

A hosted page has one origin, so the header-policy and storage lanes cannot run here; those need the local lab. What does work in a single origin is the part most people get wrong anyway: origin inheritance. A srcdoc frame, a blob: document and a sandboxed frame all acquire an origin by inheritance rather than from a URL, and a sandbox="allow-scripts" frame gets a genuine opaque origin — a real boundary to test against.

Verdict taxonomy

VerdictMeans
bypassData or DOM access crossed a boundary the policy is supposed to close. In the lab run this requires the per-run secret as evidence.
blockedThe boundary held. Expected on a patched engine — a suite without these is not measuring anything.
inconclusiveRan, but the outcome does not separate bypass from block. Side channels live here: state is inferable, no bytes cross.
unsupportedThe primitive does not exist in this engine.

A bypass is not automatically an engine bug. Several below are by-design holes in the origin model — cross-origin <script> execution, postMessage with targetOrigin: '*', a wildcard CORS header. They are genuinely exploitable and genuinely not defects in any browser. The defect is in whoever deployed them.
